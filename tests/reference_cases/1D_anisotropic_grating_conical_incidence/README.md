# 1D anisotropic grating, conical incidence — RETICOLO reference

A diagonally anisotropic grating bar sitting on a slab of the same tensor, lit
off-plane. Solved independently by meent and by RETICOLO (MATLAB), 500–700 nm.

This is the case that establishes the reference-data workflow. The recipe for
adding another is in [../README.md](../README.md).

## Structure

| | |
|---|---|
| period | 1000 nm |
| layer 1 | grating bar, width 500 nm centred at 500 nm, thickness 500 nm |
| layer 2 | uniform slab, thickness 500 nm |
| index (bar and slab) | diagonal tensor (nₓ, n_y, n_z) = (1.5, 2.0, 2.5) |
| superstrate / substrate | n = 1 / n = 1 |
| incidence | θ = 30°, conical (φ = 30°) |
| retained orders | fto = 100 (RETICOLO `nn = 100`) |
| sweep | 500–700 nm, 1 nm steps, 201 points |
| observables | R = Σ reflected efficiencies, T = Σ transmitted efficiencies |

Two things make this case worth having: the permittivity is a **tensor**, and the
incidence is **conical**, so the two polarizations couple and the solver cannot
fall back to the fast 1D path. meent routes all three modeling methods to the 2D
solver here (`grating_type_assigned == 2`).

## What is in this directory

```
reference/   RETICOLO output — the external ground truth
             RETICOLO_..._TE.txt, _TM.txt      lambda_nm, R, T
             RETICOLO_....m                    the script that produced them
recorded/    meent output at the time of the experiment — the frozen result
             Meent_..._{TE,TM}_{discrete,continuous,vector}.txt
case.py      how to rebuild the experiment in meent
```

`reference/` is never regenerated by this repo — RETICOLO is not part of the test
pipeline and needs MATLAB. `recorded/` is meent's own past answer, kept so a
change in meent is detectable even when nobody can run MATLAB.

## Provenance

**Reference.** RETICOLO, run from
`reference/RETICOLO_1D_anisotropic_grating_conical_incidence.m`. A 1D texture in
RETICOLO takes a scalar index, so the anisotropic cells are drawn with the
placeholder index 89.99999 and `parm.res1.change_index` swaps in the diagonal
tensor. `res1` is called in its full conical form and `res2` returns `TEinc` and
`TMinc` from a single solve. 201 wavelengths, 0 failures.
*RETICOLO version not recorded — please add it here.*

**meent side.** `Meent_1D_anisotropic_grating_conical_incidence.ipynb`, 1206
solves (3 methods × 2 polarizations × 201 wavelengths) in 587 s, 0 failures,
backend 2 (torch), complex128. That notebook lives in the experiment folder
outside this repository — see "Caveats" below.

**Required feature.** Diagonal anisotropy is torch-only and landed on
`feature/anisotropic-diagonal-torch` (commit 186fd07). It is **not on `main`**, so
on most checkouts the live tests here skip with that reason and only the
data-only tests run.

## Measured agreement

Recomputed from the committed files. `TOL_*` in `case.py` are these numbers with
about a decade of headroom.

**meent vs RETICOLO**, max(|ΔR|, |ΔT|) over 201 wavelengths:

| method | TE | TM | asserted tolerance |
|---|---|---|---|
| discrete | 6.25e-06 | 1.03e-05 | 1e-4 |
| continuous | 5.06e-11 | 6.20e-11 | 1e-8 |
| vector | 5.06e-11 | 6.24e-11 | 1e-6 |

**Energy conservation**, max |R + T − 1|. Every index is real and n_top = n_bot = 1,
so this must be zero; it is an absolute check on each file on its own, and it
holds for RETICOLO's output too:

| source | TE | TM |
|---|---|---|
| RETICOLO | 4.59e-11 | 9.81e-11 |
| meent discrete | 5.97e-12 | 9.76e-12 |
| meent continuous | 6.62e-12 | 1.14e-11 |
| meent vector | 2.56e-11 | 2.93e-11 |

**continuous vs vector**: 1.05e-11 — the raster-continuous and vector convolution
matrices land on the same answer, as they should.

The `discrete` method sits five to six orders of magnitude further from RETICOLO
than the other two. That is expected, not a defect: a discrete Fourier expansion
of a staircased cell converges more slowly than the analytic (continuous)
coefficients. It is why `TOL_REFERENCE['discrete']` is 1e-4 while the others are
1e-8 and 1e-6.

## Caveats

**This case cannot detect a φ sign error.** The MATLAB script uses
`angle_delta0 = -30°` and the notebook uses `phi = +30°`. The two agree to 1e-11,
but that is not evidence that the sign conventions match: the structure is
invariant under y → −y and only *summed* efficiencies are compared, so ±φ are
indistinguishable here. Establishing the convention needs a y-asymmetric
structure or a per-order comparison. Worth its own case.

**Summed efficiencies only.** R and T are sums over all orders. Two solvers can
agree on the totals while distributing power differently between orders. A
per-order comparison would be strictly stronger — the reference files would need
regenerating to carry it.

**The recorded run is not bit-reproducible.** It ran on Windows with a different
LAPACK build, and eigendecomposition ordering and rounding differ across builds.
`TOL_RECORDED` in `case.py` is therefore a guess (1e-9) rather than a
measurement — measure it on the CI machine and tighten it.

**Not committed** from the original experiment folder: `prv1.mat` (16 MB
RETICOLO intermediate), `.opju` (Origin project), `.xlsx` (the same numbers as
the `.txt` files, reorganized for plotting), and the notebook. The `.txt` files
are canonical; everything else is derived, large, or both.

**The notebook is not version-controlled.** It is the only record of how the
meent side was produced, and it currently lives only in the experiment folder.
`case.py` reproduces its solve path, but not its analysis. Consider committing it
alongside this README.
